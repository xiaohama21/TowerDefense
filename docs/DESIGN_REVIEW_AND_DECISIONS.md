## 1. 当前结论

当前项目已经具备完整的单机塔防基础和较完整的长线养成：

- 第一章 8 关可玩。
- 角色、职业、等级、转职、升星、信物、羁绊、遗物已经形成养成链。
- 大招、角色特性、技能、敌人行为和数值配置已经数据化。
- 阶段 8·提交 1 已加入职业化局内升阶和局内军需。

当前最大的风险不再是“缺少系统”，而是系统叠加后的规则不够明确、数值缺少统一预算，以及文档状态存在不一致。

建议暂时不要直接开始第二章完整制作。应先完成本文档中的 P0 项，再用第二章一关做垂直切片。

## 2. 优先级说明

| 优先级 | 含义 | 处理要求 |
|---|---|---|
| P0 | 会导致返工、存档错误或玩法失控 | 进入下一次开发前必须解决 |
| P1 | 会影响平衡、理解成本或长期体验 | 阶段 8 收尾前解决 |
| P2 | 可提升内容质量，但不阻塞主线 | 第二章或首发前解决 |
| P3 | 远期扩展 | 不提前实现 |

## 3. P0：必须先拍板的问题

### 3.1 文档版本与程序版本

**问题**

总纲使用 `v0.21.1`，README 和 `project.godot` 使用 `0.10.1-alpha`。这可以分别代表文档版本和程序版本，但目前没有统一说明，容易造成误判。

**推荐方案**

统一使用三种版本字段：

```text
文档版本：v0.22.0（文档保留 v0.x 体系）
程序版本：0.8.1.1（规则：0.阶段.提交.bug修复；当前=阶段 8·提交 1·修复 1）
开发状态：阶段 8·提交 1
```

所有文档顶部都只写与自身相关的版本；README 同时显示三项。

**需要拍板**

- [x] 接受“文档版本 / 程序版本 / 开发状态”三者分离。
- [x] 程序版本与阶段提交统一：`0.<阶段>.<提交>.<bug修复>`（阶段 8·提交 1=`0.8.1.0`；每修 1 个 bug 末尾 +1；阶段/提交上升时后续位清零；当前 `0.8.1.1`）。

### 3.2 全系统数值计算顺序与上限

**问题**

角色可能同时受到等级、转职、二转、升星、信物、羁绊、科技、遗物、局内升阶、军需、特性和技能影响。如果每个系统独立相乘，后续章节很容易出现指数膨胀。

**推荐方案**

统一计算顺序：

```text
基础属性
→ 局外成长：等级 / 转职 / 星级 / 信物
→ 编队加成：羁绊 / 科技
→ 本局开局加成：遗物
→ 本局动态加成：升阶 / 军需 / 技能 / 大招
→ 最终伤害、攻速、射程限幅
```

建议增加以下硬规则：

- 同类光环只取最高值，或明确全部采用加法，不能在不同系统中混用。
- 同类减速不叠加，只刷新持续时间。
- 最终攻速倍率设置下限，建议不低于 `0.55`。
- 普攻、技能、大招分别设置强度预算，不允许所有效果共用无限乘区。
- AOE 半径、击退距离和控制持续时间设置上限。

**需要拍板**

- [x] 采用上述计算顺序（详见 NUMBERS.md 10.10）。
- [x] 最终攻速下限采用 `0.55`（合理性待平衡测试验证）。
- [x] 同类光环采用“加法叠加但设总上限”（不取最高）。

### 3.3 每关经济预算

**问题**

现在金币可以用于建造、升阶、军需、回收，未来还会用于结算奖励。文档有单项费用，但缺少每一关的总收入、推荐支出和最低通关预算。

**推荐方案**

每个 `StageData` 增加一张设计预算表，至少包含：

```text
初始金币
预计击杀金币
波次奖励
技能额外金币
遗物额外金币
理论总收入
推荐建造数
推荐升阶次数
推荐军需次数
通关时合理剩余金币
```

每关必须满足：

- 不购买军需也存在可行通关方案。
- 军需应改变解法，而不是成为必买按钮。
- 升阶和追加建塔之间存在真实取舍。
- 回收不能通过重复建造获得正收益。

**需要拍板**

- [x] 每关以“标准难度、无遗物、无科技额外加成”作为基准预算。
- [x] 军需允许成为高难度下“不可或缺”的重要道具（标准难度不依赖军需）。
- [x] 结算奖励改为“剩余金币 ≥150 可抽取 1 次（仅 1 次）”（非评价奖励）。

### 3.4 阶段 8·提交 1 的规则完整性

**问题**

升阶和军需的功能已经实现，但以下边界需要明确：

- 升阶费用小数如何取整。
- 升阶时攻击计时器是否重置。
- 升阶是否允许在 Boss 技能前摇或胜负结算瞬间进行。
- 卖塔后重新建造是否清除升阶和怒气。
- 修整在满生命时是否禁用。
- 擂鼓是覆盖、刷新还是叠加。
- 缓兵是否影响 Boss 和召唤物。
- 火攻对护甲、Boss 阶段和后续新生成敌人的作用。
- 军需购买与胜负信号同时发生时的优先级。

**推荐默认规则**

- 所有费用向上取整。
- 升阶不重置攻击计时器，但下一次攻击使用新属性。
- 胜负结算开始后禁止新的消费。
- 卖塔后该塔所有局内状态清零。
- 满生命时修整按钮禁用。
- 同类增益不叠加，只刷新持续时间。
- 减速和灼烧对 Boss 生效，但 Boss 具有明确的抗性或持续时间折减。

**需要拍板**

- [x] 接受上述默认规则（费用向上取整；升阶不重置攻击计时器；结算开始后禁止消费；卖塔后局内状态清零；满血禁用修整；同类增益不叠加只刷新）。
- [x] 军需允许影响 Boss：减速/灼烧生效，Boss 具有明确抗性或持续时间折减。
- [x] 不加军需购买确认，保持即买即用（“结算开始后禁止消费”兜底误触）。

### 3.5 失败、退出、崩溃和重开语义

**问题**

文档已经规定失败不保存经验和掉落，但还需要明确应用关闭、进程崩溃和回到大厅时的处理。

**推荐方案**

```text
进入战斗：消耗局内遗物
战斗中：经验、升阶、军需、金币只存在 BattleSession
胜利：一次性提交 XP、掉落、解锁、科技点和关卡进度
失败 / 重开 / 退出：丢弃 BattleSession 临时内容
应用崩溃：下次启动不恢复未提交战斗
```

`run_id` 必须保证重复胜利信号只产生一次奖励。

**需要拍板**

- [x] 接受“应用崩溃也不恢复未提交战斗”（run_id 防重复提交）。
- [x] 遗物改为“关卡结算完再消耗”：胜利提交时扣库存，失败/退出/崩溃不消耗。

## 4. P1：阶段 8 收尾前应解决的问题

### 4.1 波次预算与连击节奏

当前波次主要按敌人数量描述，后续章节容易出现“数量增加但玩法没有变化”。

**推荐方案**

为敌人增加威胁点数，为每波定义预算：

```text
波次预算 = 基础兵点数 + 快速兵点数 + 精英点数 + 机制兵点数
```

每波标注自己的目的：教学、经济回收、单体压力、范围压力、漏怪压力或 Boss 前置。

连击需要明确：

- 连击窗口多长。
- Boss、召唤物和灼烧击杀是否计入。
- 波次结束是否清零。
- 攻速奖励是否有上限。
- 暂停是否冻结连击窗口。

**推荐默认值**

- 连击窗口 3 秒。
- 召唤物计入连击，但 Boss 不计入普通连击。
- 每波结束清零。
- 连击攻速奖励上限 +15%。

**拍板结论（2026-09-01，v0.3）**：接受威胁点数+波次预算方案（每波标注目的：教学/经济回收/单体压力/范围压力/漏怪压力/Boss 前置）；连击默认值全部接受（窗口 3 秒、召唤物计入/Boss 不计入普通连击、每波结束清零、攻速奖励上限 +15%）；**暂停时冻结连击窗口**。

### 4.2 结算转盘的经济风险（✅ v0.22.0 已由 P0 3.3 拍板解决）
- **拍板结论（2026-09-01）**：采用"剩余金币 **≥150 抽 1 次（仅 1 次）**"，不采用评价奖励（方案 A），不做超额兑换（方案 B），也不暂缓；单次上限 + 150 门槛避免"囤钱最优解"，详见 3.3 与 NUMBERS.md 10.9。


“剩余金币每 100 抽一次，最多 3 次”会鼓励玩家故意不升阶、不买军需，可能让错误的囤钱策略变成最优解。

**推荐方案 A：胜利评价奖励**

根据基地剩余生命、剩余金币、未使用军需和通关时间计算评价，再发固定范围奖励。

**推荐方案 B：超额金币兑换**

只将超过本关安全储备线的金币用于奖励，例如超过 `150` 金币的部分才转换，且奖励内容固定、可预览。

**不建议**

让结算奖励直接与所有剩余金币线性绑定。

**需要拍板**

- [ ] A：评价奖励。
- [ ] B：超过安全储备线后兑换。
- [ ] 暂缓结算转盘，先采集阶段 8 经济数据。

### 4.3 自由建造与地图校验

自由建造不是单纯把建造位删掉，还需要防止玩家把塔放到无效位置或地图出现不可解布局。

**推荐方案**

增加地图校验器，检查：

- 道路、入口、基地和禁建地形不重叠。
- 每条路线存在完整通路。
- 每条路线至少有两个有效覆盖区。
- 每种职业至少存在一个可用位置。
- 远程、近战和投石车都有合理位置。
- 建造预览不会与已有塔、基地和入口重叠。

推荐位保留为软引导，只提供类型标签和高亮，不给予额外数值加成。

**需要拍板**

- [x] 自由建造采用 80px 网格吸附；**非建造位（空地）均可建造**，不固定建造地点（v0.3 拍板）。
- [x] 推荐位只做视觉引导（类型标签+高亮），**不允许强制**、无数值加成。
- [x] 允许塔之间射程重叠，不允许实体重叠。

### 4.4 科技树分类与重置

阶段 8 提交 3 计划将三分支调整为四类分页，但需要说明旧科技数据如何迁移。

**推荐分类**

- 军略：职业和伤害相关。
- 后勤：金币、波次奖励和军需。
- 工事：基地生命、建造和回收。
- 将略：怒气、技能和机制分支。

建议：

- 已解锁科技不丢失，只迁移到新分类。
- 科技点不可负数。
- 提供一次免费重置或明确“不提供重置”。
- 所有科技全点后的全局增益仍受统一上限控制。

**需要拍板**

- [x] 允许科技重置，**无条件**（免费、不限次数、全额返还科技点，v0.3 拍板）。
- [x] 重置全额返还科技点（不做 80% 折损）。
- [x] 新分类采用四类名称：军略/后勤/工事/将略。

### 4.5 辅助角色经验与贡献事件

角色文档已经规定舞娘和辅助武将可通过增益、光环覆盖获得经验，但行为文档仍有“塔侧辅助贡献台账待建”的旧描述。

**推荐方案**

统一建立贡献事件：

```text
damage_dealt
kill
buff_applied
aura_covered_time
debuff_applied
```

经验系统和怒气系统订阅同一事件流，但使用不同换算系数。

必须增加防刷限制：

- 光环覆盖按时间分段结算，不按每帧结算。
- 同一增益对象在短时间内重复刷新不重复给满额贡献。
- 贡献经验设置每波上限，避免辅助塔只需挂机就超越输出塔。

**需要拍板**

- [x] 采用统一贡献事件流（`damage_dealt`/`kill`/`buff_applied`/`aura_covered_time`/`debuff_applied`），经验与怒气订阅同一事件流、不同换算系数。
- [x] 辅助贡献经验设置每波上限（防挂机超越输出塔）；光环按时间分段结算、同增益短时重复刷新不重复给满额。

## 5. P2：玩法体验建议

### 5.1 增加可选挑战目标（✅ v0.4 已拍板，阶段 10 排期）

普通胜利之外，每关可以提供 2~3 个可选目标：

- 不使用军需通关。
- 基地保持 80% 以上生命。
- 不卖塔通关。
- 只使用指定职业。
- 限时通关。
- 击败全部精英。

奖励建议为称号、头像框、少量材料或剧情，不要让挑战目标成为主线硬门槛。

**拍板结论（2026-09-01，v0.4）**：接受加入挑战目标系统（仅作为结算页附加项，不改变关卡流程、不设主线硬门槛）；首批目标池采用 3 个零新 UI 成本、可自动判定的目标——不使用军需通关 / 基地生命 ≥80% 通关 / 击败全部精英；奖励采用"少量材料 + 结算页目标勾选与关卡星级（0~3 星）"，暂不做称号与头像框系统。数值与排期见 NUMBERS.md 10.11、STAGES.md 5.8、GAME_DESIGN.md 阶段 10。

### 5.2 降低系统学习成本（✅ v0.4 已拍板，开发计划排期靠后）

系统数量已经较多，建议按进度逐步开放：

```text
第 1~2 关：建造、开波、基础职业
第 3~4 关：大招、技能、敌人机制
第 5 关：升阶、回收、军需
第 6~7 关：遗物、羁绊、科技
第 8 关：Boss 综合挑战
```

已经完成的系统也不必在第一关全部展示，可以按首次使用时弹出一次简短说明。

**拍板结论（2026-09-01，v0.4）**：接受渐进解锁节奏（1~2 关建造/开波/基础职业；3~4 关大招/技能/敌人机制；5 关升阶/回收/军需；6~7 关遗物/羁绊/科技；8 关 Boss 综合）；解锁依据=关卡通关进度，仅解锁"系统入口"，已拥有/已通关内容不限制使用；引导方式=首次使用时弹一次简短说明（可跳过、不重复弹）。**开发计划排期靠后（总纲阶段 10），设计定稿不阻塞阶段 8/9。**

### 5.3 统一敌人设计模板（✅ v0.4 已拍板）

每个新敌人都应具备：

```text
一个主要能力
一个清晰预警
至少两个有效反制
一个失败保护机制
```

### 5.4 Boss 设计模板（✅ v0.4 已拍板）

每个 Boss 至少包含：

- 登场预警。
- 两到三个阶段。
- 每阶段一个新行为。

- 阶段切换后的输出窗口。

### 12.6 议题四/五：经验获取与军需重构（2026-09-10 拍板；排期 阶段 8·提交 15 = 0.8.15 / 提交 16 = 0.8.16）

#### 12.6.1 经验池（排期 0.8.15）

1. **经验池（方案 A：结算注入 + 自由分配）**：胜利结算时按 **50% 系数额外注入**——`注入 =（本局击杀经验总量 + participant_xp × 出战人数）× 50%`；**不扣减**武将自身所得经验（纯增量）。失败 / 退出 / 崩溃作废（沿用现有结算语义）。
2. **池内分配**：余额可分配给任意**已拥有**武将（含未出战、后解锁；满级武将不可分配）；**分配不可逆**、操作前二次确认；分配即计入该武将 `total_exp`。
3. **不加"溢出转池"**：30 级封顶**不**产出池经验（用户拍板"不需要"）；池只由胜利结算注入。
4. **练兵令整体删除**：`exp_scroll`（背包测试发放按钮 + 养成面板"使用练兵令"行）随 0.8.15 一并删除；**养成面板角色详情改为"直接升级"**——消耗池内经验升 1 级（二次确认）。
5. **不变项**：击杀经验归属（末击 50% + 参与者均分）、贡献事件流、落后补正（+20%/级差、≤+60%）、等级上限 30 全部保留。
6. **落地口径**：各关注入测算与追赶节奏见 NUMBERS 10.14（标注"按 0.8.13 前配置"，扩充落地后重算）；存档字段 `exp_pool` 见 SAVE_DATA 8；UI（余额 + 分配 + 直接升级）见 UI_LAYOUT §6。

#### 12.6.2 军功 + 军需重构（排期 0.8.16）

1. **军功（新货币）**：来源 = **击杀掉落固定值**（与经验同通道、胜利结算提交；失败 / 退出**不带出**）；困难难度 **×1.5**。档位——步卒 / 弓手 = **1**；轻骑 / 祭酒 = **2**；力士 / 伍长（含 0.8.13 新精英：精锐伍长 / 披甲力士 / 夜行刺 / 隐方士 / 符祭）= **3**；Boss = **25**（张梁 / 张宝），张角（终 Boss）草案上调 **40（待确认）**。各关合计与全章测算见 NUMBERS 10.15。
2. **军需池 = 6 件**：基础 4 件**全保留**（修整 60·限 1 / 火攻 80·限 1 / 擂鼓 50·限 2 / 缓兵 40·限 2）+ 新增 2 件——**掷石齐射**（全场敌人各受 60 物理伤害，70 金，限 1）、**犒军**（全队怒气 +20，50 金，限 1）；**坚壁 / 伤药 / 火油罐移除**（火油罐不留二期候选）。
