## 1. 游戏概述

- **类型**：单机章节制塔防（普通关 10~15 分钟、Boss 关 20~30 分钟，v0.7 统一口径），带局外养成（Roguelite-lite）。
- **核心概念**：玩家防守的"塔"就是具体三国人物（如关羽、黄忠）。每个武将属于一个职业（骑兵、弓箭手、术士、舞娘等），拥有独立的等级、经验、转职路线与技能。
- **一句话玩法**：选择关卡 → 编队出征 → 在战场上建造武将塔 → 击杀敌军波次 → 守住基地 → 通关结算（经验、掉落、角色解锁）→ 养成武将 → 挑战更强关卡。
- **双循环**：
  - 局内循环（每局 10~30 分钟）：经济（杀怪金币）→ 建造/升级武将 → 防御波次 → 胜利或失败。
  - 局外循环（长期）：经验 → 等级 → 转职 → 更强的武将 → 解锁新关卡/新角色 → 掉落 → 抽奖。

## 2. 核心玩法循环（详细）

```
主菜单
  └─ 章节选择（第一章：黄巾之乱）
	   └─ 关卡选择（按顺序解锁，可重刷已通关关卡）
			└─ 编队（从已拥有武将中选出 squad_size 个出战）
				 └─ 战斗
					  ├─ 波次准备期：查看敌人预告，规划建造
					  ├─ 波次进行中：建造武将塔、击杀获得金币与经验
					  ├─ 失败：基地生命归零 → 结算失败 → **局内经验/掉落全部作废**
					  └─ 胜利：清空全部波次 → 结算
						   ├─ 参战武将获得经验（含击杀经验与通关参与经验）
						   ├─ 获得首通/重复通关掉落
						   ├─ 解锁新武将（首通奖励）
						   └─ 解锁下一关（按 prerequisite_stage_ids）
				 └─ 养成界面（武将详情）
					  ├─ 升级（消耗经验自动结算）
					  ├─ 转职（满足等级 + 消耗材料）
					  └─ 抽奖【阶段4】求贤令 → 新武将 / 碎片
```

**核心规则（不可违背）**：局内获得的所有经验、掉落、解锁均先进入"会话暂存"（`BattleSession` 的 pending 数据），**只有通关胜利后才提交写入存档**；失败、中途退出、放弃一律作废。该规则已由现有 `BattleSession` + `PlayerProfile.apply_battle_session()` 实现，后续不得绕过。

- 每章约 6~10 关，最后 1~2 关为 Boss 关。

- 第二章之前不开发任何新章节内容，但 `ChapterData` 数据结构已支持多章，`is_currently_available` 控制展示。

- **设计预留（暂不开发）——局内觉醒**：以金币对已建塔进行临时转职（本局生效、结算还原）；仅预留 `battle_rank` 扩展口、不做任何功能；风险：与升阶/转职/科技叠加强度可能失控，后续视平衡数据再排期。
- **验收标准**：局内金币始终有明确用途（建造/升阶/军需/转盘）；任意关卡空地皆可建、推荐位不再硬限制；科技树四页签浏览顺畅、成语命名一目了然；一场胜利局可稳定触发军需购买与连击奖励；转盘（≥150 金抽 1 次）结果正确入账、失败作废；遗物在胜利结算时扣除、失败/退出/崩溃不扣；**界面排版符合 UI_LAYOUT.md v0.1（地图 2×4 无滚动条、养成页签化、语义色板统一）**。
- **不做**：觉醒开发；第二~七章内容；正式美术替换；局外金币化。

### 阶段 9：升阶特性与分支（v0.20.1 设计定稿，待开发）

- **目标**：让局内升阶从"堆数值"升级为"局内构筑"——3 阶解锁职业特性（减速/眩晕/灼烧等被动效果）、5 阶特性强化与分支选择，给玩家更多搭配与选择性。依赖阶段 8 的职业化升阶先落地。
- **术语**：升阶特性（`battle_trait`，局内临时、随局结束失效）与角色常驻特性（`trait_id`）严格区分；两者可叠加但独立配置。
- **提交 1（待开发）——3 阶特性解锁**：每职业 1 个被动效果（草案：虎贲命中概率眩晕、骑兵命中减速、弓箭手减速箭、术士范围灼烧、投石车落点灼烧区域、舞娘/辅助光环附加增伤）；命中触发、带概率/冷却上限防失控（数值见 NUMBERS.md 10.9）。
- **提交 2（待开发）——5 阶特性强化 + 分支选择**：5 阶时特性强化（效果提升/范围扩大），并在 2~3 个候选分支中**选择其一**（本局生效、不可更换，候选按职业配置）；入口位于已建塔交互面板。
- **提交 3（待开发）——敌人/Boss 设计模板回填（P2 拍板，见 DESIGN_REVIEW_AND_DECISIONS.md 5.3/5.4）**：第一章现有敌人按模板补齐——每个敌人 1 个主要能力 / 1 个清晰预警 / 至少 2 个有效反制 / 1 个失败保护机制（禁止高血/高甲/高速/治疗/召唤堆叠）；Boss 张梁补充分阶段设计（2~3 阶段、每阶段一个新行为、技能前摇与可识别范围、阶段切换输出窗口、召唤数量上限）；控制抗性递增生效——每阶段控制时长减免 30%、上限 60%、非永久免疫（见 NUMBERS.md 10.11）；新增敌人/Boss 必须先满足模板再建数据。
- **验收标准**：每种职业可玩出至少 1 种特性流派；5 阶分支选择有明确取舍、无绝对最优解；特性数值不叠加出"秒杀级"效果。
- **不做**：特性随机词条；升阶特性与角色专属特性融合；分支可重复切换。

### 阶段 10：玩法体验完善（P2 拍板定稿，待排期）

- **目标**：提升内容质量与上手体验，不阻塞主线——结算挑战目标 + 系统渐进解锁（降低学习成本）。设计定稿见 DESIGN_REVIEW_AND_DECISIONS.md 5.1/5.2。
- **提交 1（待排期）——可选挑战目标**：每关结算附加 3 个全局目标（不使用军需通关 / 基地生命 ≥80% 通关 / 击败全部精英，自动判定，见 STAGES.md 5.8）；每达成 1 个奖励少量材料（草案：黄巾布 ×2，见 NUMBERS.md 10.11）；达成数 = 关卡星级（0~3 星）写入存档，重复通关取历史最优；挑战目标不设主线门槛、不锁定任何内容。
- **提交 2（待排期）——系统渐进解锁与首用说明**：按关卡通关进度解锁系统入口（节奏：1~2 关建造/开波/基础职业；3~4 关大招/技能/敌人机制；5 关升阶/回收/军需；6~7 关遗物/羁绊/科技；8 关 Boss 综合）；已拥有/已通关内容不限制使用；首次使用弹一次简短说明（可跳过、不重复弹）。

## 12. 防跑偏铁律（Do / Don't）

- ✅ 内容一律走 `.tres` 配置；❌ 禁止在脚本里硬编码角色/敌人/关卡数值。
- ✅ 经验/掉落/解锁必须通关后才提交；❌ 禁止任何"失败也保留成长"的旁路。
- ✅ 每个阶段结束可完整游玩；❌ 禁止开发未排期的【远期】内容（多分支转职、二转、抽奖 UI、后续章节）。
- ✅ 抽奖只加速、不卡主线；❌ 禁止让抽奖成为获取关键流程角色的唯一途径。
- ✅ 挑战目标只作结算附加项；❌ 禁止因未达成挑战目标而锁定内容或卡主线进度。
- ✅ 新增敌人/角色先建数据再写行为；❌ 禁止为单角色硬编码攻击逻辑。
- ✅ 修改数值/玩法设计必须先更新对应设计文档（总纲或模块文档）；❌ 禁止文档与实现分叉后继续开发。
- ✅ 转职不可逆，`promotion_path` 记录历史；❌ 禁止转职回退或重复转职。
- ✅ 大招与特性通过配置字段 + 行为 ID（`ultimate_id` / `trait_id`）驱动；❌ 禁止在塔脚本中硬编码某角色的专属逻辑（行为注册表见 modules/BEHAVIORS.md）。
- ✅ 怒气与局内升级等级为临时状态；❌ 禁止怒气/大招/局内升级等级写入存档。
- ✅ 保持单机、本地存档；❌ 禁止在 2026 年前规划联机/云存档/内购（【远期】另行立项）。
