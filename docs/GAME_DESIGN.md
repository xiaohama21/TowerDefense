## 1. 游戏概述

- **类型**：单机章节制塔防（普通关 10~15 分钟、Boss 关 20~30 分钟，v0.7 统一口径），带局外养成（Roguelite-lite）。
- **核心概念**：玩家防守的"塔"就是具体三国人物（如关羽、黄忠）。每个武将属于一个职业（骑兵、弓箭手、术士、舞娘等），拥有独立的等级、经验、转职路线与技能。
- **一句话玩法**：选择关卡 → 编队出征 → 在战场上建造武将塔 → 击杀敌军波次 → 守住基地 → 通关结算（经验、掉落、角色解锁）→ 养成武将 → 挑战更强关卡。
- **双循环**：
  - 局内循环（每局 10~30 分钟）：经济（杀怪金币）→ 建造/升级武将 → 防御波次 → 胜利或失败。
  - 局外循环（长期）：经验 → 等级 → 转职 → 更强的武将 → 解锁新关卡/新角色 → 掉落 → 抽奖。

## 2. 核心玩法循环（详细）

```
主菜单
  └─ 章节选择（第一章：黄巾之乱）
	   └─ 关卡选择（按顺序解锁，可重刷已通关关卡）
			└─ 编队（从已拥有武将中选出 squad_size 个出战）
				 └─ 战斗
					  ├─ 波次准备期：查看敌人预告，规划建造
					  ├─ 波次进行中：建造武将塔、击杀获得金币与经验
					  ├─ 失败：基地生命归零 → 结算失败 → **局内经验/掉落全部作废**
					  └─ 胜利：清空全部波次 → 结算
						   ├─ 参战武将获得经验（含击杀经验与通关参与经验）
						   ├─ 获得首通/重复通关掉落
						   ├─ 解锁新武将（首通奖励）
						   └─ 解锁下一关（按 prerequisite_stage_ids）
				 └─ 养成界面（武将详情）
					  ├─ 升级（消耗经验自动结算）
					  ├─ 转职（满足等级 + 消耗材料）
					  └─ 抽奖【阶段4】求贤令 → 新武将 / 碎片
```

**核心规则（不可违背）**：局内获得的所有经验、掉落、解锁均先进入"会话暂存"（`BattleSession` 的 pending 数据），**只有通关胜利后才提交写入存档**；失败、中途退出、放弃一律作废。该规则已由现有 `BattleSession` + `PlayerProfile.apply_battle_session()` 实现，后续不得绕过。

以三国历史主线为骨架，章节从黄巾之乱开始，到五丈原结束。

## 11. 开发阶段规划

**总原则**：每个阶段结束时游戏可独立游玩；阶段顺序不可跳；【远期】内容只做数据结构预留，不做功能。

### 阶段 2：角色养成（升级与一转）

- **目标**：武将可升级、可转职，养成结果持久且可感知。
- **范围**：
  - 武将详情界面（等级、经验条、属性、转职按钮）。
  - 转职流程（等级+材料校验、消耗、`promotion_path` 写入、数值/外观应用）。
  - 补齐全部已有角色的一转配置（刘备/黄忠/貂蝉 + 新角色；v0.7 已建占位资源，本阶段细化数值）。
- **验收标准**：角色升到 10 级可转职；转职后伤害/攻速变化可感知；重启游戏状态不变；材料不足时无法转职。
- **不做**：多分支、二转、升星。

  - 新增角色：周仓（枪兵）、赵云（枪兵）、诸葛亮（数据+特性+解锁关）。
  - **落地怒气/大招/特性基础机制**：数据字段扩展（见 modules/CHARACTERS.md 4.7 汇总）、行为注册表扩展至大招/特性/敌人特殊行为（见 modules/BEHAVIORS.md）、数值生效；表现仅占位（无特效，怒气条可用）。
  - 章节选关界面完成、首通解锁/奖励全量配置。
- **验收标准**：全新存档可连续打穿第一章至 Boss 关；全角色收集；Boss 战可依赖大招通关；**每个角色特性与职业大招数值生效；怒气每局重置、不进存档**；无配置缺失报错（`tests/SmokeRunner.gd` 资源完整性扫描兜底）。
- **不做**：抽奖、多分支转职、大招特效演出。

### 阶段 4：掉落与抽奖

- **目标**：重复刷关有价值，求贤抽奖可用且有保底。
- **范围**：
  - 重复通关掉落表（`repeat_clear_rewards` + 敌人 tags 掉落倾向）。
  - 求贤界面、卡池配置、单抽/十连、保底。
  - 重复角色 → 碎片；碎片可抵扣转职材料。
  - 启用 `gacha_state` 存档。
- **验收标准**：刷关可稳定获得材料；抽奖产出符合概率配置；保底生效；主线流程不被抽奖阻塞。
- **不做**：任何付费/内购/货币充值。

### 阶段 5：技能、怒气大招与演出差异化

- **目标**：每个武将的技能与大招可辨识、有演出，战斗有爽感。
- **范围**：逐个落实 `initial_skill_ids`（如关羽青龙斩、黄忠穿透箭）；职业大招演出（特效/音效/怒气条美化）；特性触发反馈（飘字/光效）；Boss 战演出；评估手动释放大招开关【待定】。
- **验收标准**：每个角色至少一个可辨识技能 + 一个可辨识大招；大招释放有明确正反馈；通关过程有爽感。
- **不做**：UI 大改、新系统、多分支转职。

### 阶段 6：扩展地基（远期框架，只做试点）

- **验收标准**：试点角色完成多分支转职全流程；模板可支撑第二章直接堆内容。
- **不做**：第二章正式内容。

## 12. 防跑偏铁律（Do / Don't）

- ✅ 内容一律走 `.tres` 配置；❌ 禁止在脚本里硬编码角色/敌人/关卡数值。
- ✅ 经验/掉落/解锁必须通关后才提交；❌ 禁止任何"失败也保留成长"的旁路。
- ✅ 每个阶段结束可完整游玩；❌ 禁止开发未排期的【远期】内容（多分支转职、二转、抽奖 UI、后续章节）。
- ✅ 抽奖只加速、不卡主线；❌ 禁止让抽奖成为获取关键流程角色的唯一途径。
- ✅ 新增敌人/角色先建数据再写行为；❌ 禁止为单角色硬编码攻击逻辑。
- ✅ 修改数值/玩法设计必须先更新对应设计文档（总纲或模块文档）；❌ 禁止文档与实现分叉后继续开发。
- ✅ 转职不可逆，`promotion_path` 记录历史；❌ 禁止转职回退或重复转职。
- ✅ 大招与特性通过配置字段 + 行为 ID（`ultimate_id` / `trait_id`）驱动；❌ 禁止在塔脚本中硬编码某角色的专属逻辑（行为注册表见 modules/BEHAVIORS.md）。
- ✅ 怒气与局内升级等级为临时状态；❌ 禁止怒气/大招/局内升级等级写入存档。
- ✅ 保持单机、本地存档；❌ 禁止在 2026 年前规划联机/云存档/内购（【远期】另行立项）。
