## 1. 定位与边界

1. **工具定位**：地图编辑器是**布局数据（`StageData` 布局字段）的可视化生产工具**——所见即所得地铺路、摆装饰、标禁建、点建造位，一键校验并导出为运行时同一 schema 的 `.tres`。它不是运行时模块，不替代美术资产生成，不改变战斗逻辑。
2. **模块化含义**：地图 = 「网格布局数据（道路/装饰/禁建/建造位/出入口） + 主题（grass/fire/night） + 美术素材（瓦片/装饰/地标）」三件套组合；编辑器产出前两者，素材按 [ART_ASSETS.md](ART_ASSETS.md) §4 目录（`assets/map/themes/`、`assets/map/decor/`、`assets/map/terrain/`、`assets/map/landmarks/`）就位后自动反映到预览。
3. **v1 范围（本次排期）**：
   - 载入/新建 `StageData` 关卡布局；编辑主路径、装饰格、禁建格、建造位（软引导推荐位）；
   - 实时校验（复用 `tools/map_validator.gd` 规则）+ 错误/警告面板；
   - 导出：覆盖保存 `.tres`（布局字段，其余字段原样保留）+ 可选导出纯底图 PNG（供美术手绘打底）。
4. **v2 范围（暂不排期）**：`fork_path_points` 分叉路径编辑（s08 型）、波次/敌人组、剧情对话、经济预算字段、类型化建造位（`BuildSlotData` 读取展示可先行）。v1 遇到此类数据只读展示并提示「v2 范围」。
5. **非目标**：不生成美术素材（瓦片/装饰/立绘）；不做网页版；不参与 UI/大厅界面；不改运行时布局推导与渲染管线。

## 2. 现状与背景

- 运行时布局口径（v0.9 数据驱动化）：`path_points`（直角折线，含图外延长段）→ `GridBackground.derive_road_cells()` 逐格推导道路格；出入口地标取主路径首/末图内格；`decor_cells` / `forbidden_cells` / `build_slot_positions`（s08 另含结构化 `build_slots`）直接使用；网格固定 **16 列 × 9 行、80px/格、1280×720**。
- 现有校验器 `tools/map_validator.gd`（独立运行 + `validate_stage` 静态方法，供编辑器直接调用）：禁建不与道路/出入口重叠、主路径完整连通、覆盖区 ≥2 组 / 贴路可建格 ≥4、近战贴路位与中远程位齐备。
- 地图素材现状：`assets/map/decor/` 已有四类装饰（tree/rock/banner/torch），主题瓦片/地形/地标目录为空；`GridBackground` 全部支持素材缺失回退程序化绘制——编辑器预览与运行时共用该实现，天然不依赖素材到位。
- **立项背景（2026-09-04 拍板）**：逐关手绘概念图 + 手写坐标不可扩展（s01 概念稿未采纳）；用户原意即模块化地图，拍板先自建编辑器，v1 满足「布局编辑 + 导出」。

## 3. 技术方案

### 3.1 宿主与入口

- 实现为 **Godot 编辑器插件（EditorPlugin）**，代码入 `addons/map_editor/`（`plugin.cfg` + 工具脚本 + 场景），仅编辑器启用，不影响游戏导出与运行。
- 入口：编辑器菜单 → 项目 → 工具 → 「地图编辑器」，打开独立编辑窗口（画布 1280×720，可缩放平移）。
- **画布显示口径（v0.4）**：画布内容固定按 1280×720 逻辑分辨率布局（SubViewport `size_2d_override` + `size_2d_override_stretch`），外层 `AspectRatioContainer` 16:9 等比缩放居中——窗口大小只改变显示比例、不裁切内容，网格数量与运行时 16×9 恒一致（BUGS B-030）。
- 编辑器内实例化现有 `GridBackground`（`configure(...)`）作为**底图预览层**，保证「编辑器所见 = 运行时所得」；编辑态附加层（建造位虚线圆、出入口旗标、网格线、选中高亮）叠加其上，导出底图 PNG 时剔除编辑态附加层。

### 3.2 数据模型与编辑交互

- 画布即 16×9 网格，坐标口径与运行时一致（格中心 = `(40+80×c, 40+80×r)`）。
- **主路径（v1 单链限制）**：以「路径刷」在网格上逐格延伸/退格（每次只在链端点格向 4 邻空格延伸，或删除端点格），保证天然正交连通、无分叉、无环；编辑器据格链自动生成 `path_points`（端点格中心 + 转折格中心，首/末自动外延 80px 至图外）。路径端点格即出入口/基地落点，可手动「设为入口端/基地端」反转方向。
- **装饰格 / 禁建格 / 建造位**：三种刷子点涂与擦除；建造位沿用运行时软引导语义（v1 仅坐标；s08 型类型化槽位 v2）。
- **主题**：grass / fire / night 下拉切换，即时预览（同 `GridBackground.THEMES`）。
- 属性面板：显示当前关卡 id、路格数、装饰/禁建/建造位数、出入口坐标；保存前强制校验。

### 3.3 校验与导出

- **校验**：保存前调用 `MapValidator.validate_stage()`（复用现规则），另加编辑器级检查：建造位不与道路/禁建重叠（error）；装饰格与道路重叠 = warning（s01 现数据即含此类重叠，保留兼容不阻塞）；装饰/禁建与建造位重叠 = warning。错误列表实时显示于状态条，**有 error 默认阻止导出**（可勾选强制）。
- **导出 .tres**：`ResourceSaver.save()` 覆盖目标 `resources/stages/<chapter>/ch0X_sNN.tres`；仅修改布局相关字段，波次/剧情/经济等字段原样透传（整资源重存）。
- **导出底图 PNG（可选）**：剔除编辑态附加层后截图预览层，存 `assets/map/themes/<theme>/layout_<stage_id>.png`（纯底图、供美术手绘重绘打底）。
- 新增关卡流程（编辑器外仍按现有规范）：创建 `.tres` 骨架（波次/剧情/经济等）→ 编辑器编排布局 → 校验通过 → 在 [STAGES.md](STAGES.md) 第一章规划登记。编辑器在保存成功提示中输出该 checklist，不自动改文档。

## 6. 兼容与风险

1. **运行时零侵入**：编辑器只读写 `.tres` 布局字段；`addons/` 插件不进运行时逻辑路径（编辑器专用）。
2. **整资源重存产生大 diff**：`ResourceSaver` 重写 `.tres` 可能调整子资源 id/顺序，git diff 较大；属预期，评审按字段 diff 核对，必要时以 `git checkout` 单文件回滚。
3. **预览一致性依赖运行时实现**：若 `GridBackground` 渲染演进（如主题调色板改名），编辑器因复用同一实现自动同步，无需双维护。
4. **v1 不支持分叉/环/多路**：s08 `fork_path_points` 关只读提示，编辑需手工（v2）。
5. **素材未到位不影响使用**：预览与游戏一致走程序化回退；主题瓦片入库后自动增强。
