## 1. 归属与边界

`CharacterData.faction: StringName`取`wei/shu/wu/qun`；字段与`tags`独立。刘备、关羽、张飞、赵云、黄忠、周仓（资源ID `zhou_wei`）、诸葛亮属蜀，共7名；貂蝉、皇甫嵩属群，共2名。魏、吴本章暂无武将，保留筛选和徽记。

从九将`tags`移除`shu/han`等阵营值，保留职业、支援等用途标签；不在玩家档案写阵营，不新增迁移和schema。资源归属可供旧档直接读取，已有等级、品阶、技能、装备、天赋和编队记忆保持有效。

阵营本身没有属性、伤害、怒气或掉落加成。现有桃园结义和五虎将仍按成员ID激活，数值与编队桶保持；阵营组合羁绊留待后续章节。限制不会改变已有库存、购买和掉落。

## 2. 展示与筛选

使用现有`faction_wei/shu/wu/qun`四枚徽记，标记为已接入；图标目录维持393枚。按用户反馈与AGENTS §6.9，阵营采用军旗图徽＋常显中文“魏/蜀/吴/群”，蓝/绿/红/紫仅作辅助；悬停仍提供完整归属提示，武将名称及已有技能、物品文字保留。

百科武将列表头部增加“全部”按钮和四枚军旗＋中文阵营按钮，直接显示各组数量（9/0/7/0/2），同一行互斥选中，可用键盘激活。筛选作用于所有已实装武将，不按玩家拥有情况过滤。原始九将顺序保持；当前武将在结果中则保留选中和模拟进度，否则切到结果中首名并重置模拟。切到空阵营时清空详情和隐藏模拟器，显示“暂无武将，可切换筛选查看。”，不能查看或分配上一武将的天赋；切回全部恢复默认/首名。切换敌人图鉴隐藏阵营筛选，返回武将图鉴保留筛选，不混用敌方阵营。

百科武将卡徽记与品阶纵向成组，避免新增一列挤压姓名；卡片最小高度64px，五行超高时由列表滚动承载，末卡可完整滚入可视区。详情头部补归属徽记，身份标签按右栏可用宽度折行，完整保留职业、称号、天赋入口及获取方式，不撑宽大厅。养成属性头部和编队角色卡、出战确认行同步显示徽记，尺寸20~24px，留4~8px间距，不挤压技能页或动作按钮。

## 3. 关卡限制接口

`StageData.faction_rule: Dictionary = {}`，仅支持`allow`和`deny`两个键，值为阵营ID数组。空规则/空数组表示不限；非空`allow`只允许列出的阵营，`deny`排除列出的阵营，冲突时禁用优先。未知ID、错误类型、未知键属于无效配置，不允许绕过；编队界面显示规则异常短句，全部禁选，不遍历格式错误的值。

共用`FactionRegistry`校验和匹配；`StageData.allows_character()`、GameFlow编队校验、编队记忆恢复/点选/确认和最终入场均使用它。限制卡禁选但可看提示，受限关卡显示动作词“限用/禁用”与对应徽记；不保存不合法编队、不进入战斗。第一章八关全部空规则，保持当前出战范围；第二章内容不在本提交。

## 4. 物品限制接口

`WeaponData/RelicData/BattleSupplyData.faction_limit: Array[StringName] = []`，空为不限，非空为允许阵营集合。未知ID配置无效。武器继续叠加职业条件，信物继续沿用槽位和库存规则；军需仅提供资源匹配接口，后续新限定军需接入时使用，当前六件为空。

武器`fits()`与信物`fits()`用于装配、属性计算和百科模拟；不匹配不能新增装配，也不计入属性。装备卡和信物详情在存在限制时显示“限用”与阵营徽记（军旗＋常显中文归属），无条件物品不额外占行。当前12款武器、已有信物与军需均不限，不把归属限制扩散为购买/掉落限制。
